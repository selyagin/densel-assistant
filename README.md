# Densel Assistant — сайт для контроля оплат

Автономное веб-приложение (PWA) на чистом HTML/CSS/JS без сервера и без облачных
сервисов, кроме самого GitHub. «Базой данных» служит файл `data.json` в этом же
репозитории — админ читает и пишет его прямо из браузера через GitHub API,
клиент (сестра) только читает.

## Сайт уже создан

Репозиторий и все файлы уже загружены: https://github.com/selyagin/densel-assistant

Включите Pages: **Settings → Pages → Source: Deploy from a branch → branch `main` / `root`**.
Сайт появится через 1–2 минуты по адресу `https://selyagin.github.io/densel-assistant/`.

## Структура репозитория

```
/
├── index.html      — вход + единая страница с экранами клиента и админа
├── style.css        — оформление, анимации, темная тема
├── app.js            — вся логика: авторизация, CRUD, графики, синхронизация с GitHub
├── data.json         — учётные записи, поставщики, платежи (это и есть "БД")
├── manifest.json      — настройки PWA (иконка, имя при установке на экран)
└── sw.js               — service worker для офлайн-кэша интерфейса
```

## Г 1. Создать токен для сохранения изменений

Приложение статично, так что «сохранить платёж» — это коммит обновлённого `data.json`
через GitHub API. Нужен токен:

1. На github.com: **Settings профиля → Developer settings → Personal access tokens →
   Fine-grained tokens → Generate new token**.
2. Repository access: **Only select repositories** → выберите `densel-assistant`.
3. Permissions → **Contents: Read and write**. Больше ничего не давайте.
4. Expiration — например 90 дней (потом просто сгенерируете новый).
5. Скопируйте токен (показывается один раз).

## Шаг 2. Войти и настроить приложение

1. Откройте сайт, войдите под админом:
   - Логин: `densel_admin`
   - Пароль: `Vtb#Densel26!`
2. Сразу зайдите в **Настройки** и заполните:
   - GitHub логин: `selyagin`
   - репозиторий: `densel-assistant`
   - ветка: `main`
   - Personal Access Token — вставьте токен из шага 1.
3. Нажмите «Сохранить настройки» — они останутся только в памяти этого
   устройства (localStorage), токен никуда кроме GitHub API не отправляется.
4. Сразу же в разделе **Сменить пароль** задайте свой реальный пароль вместо
   `Vtb#Densel26!`, а также смените пароль сестры (`sister` / `Densel2026`) —
   и сообщите ей новые данные для входа.

После этого можно добавлять/редактировать/удалять платежи — каждое изменение
сразу коммитится в `data.json` в репозитории, и через 30–60 секунд обновление
подтянется у сестры при обновлении страницы.

## Как это работает у сестры

Она заходит на тот же адрес сайта под своим логином — видит только
read-only-версию: сколько начислено, сколько оплачено, статусы (оплачено /
ожидает / просрочено / оплачено заранее) и графики статистики. Вводить или
менять данные она не может — в интерфейсе клиента нет ни одной кнопки
редактирования.

## Логика статусов платежей

- **Просрочено** (красный, с пульсацией) — срок оплаты прошёл, а сумма не
  внесена полностью.
- **Оплачено заранее** (фиолетовый) — платёж за будущий месяц полностью
  закрыт; в верхнем блоке отображается «Оплата заранее: N мес.».
- **Оплачено частично** (голубой) — внесена часть суммы.
- **Оплачено** (зелёный) — сумма внесена вовремя.
- **Ожидает оплаты** (жёлтый) — срок ещё не наступил, оплаты не было.

Всё считается на лету из `amountDue`, `amountPaid`, `dueDate` и `period` —
никаких скрытых полей менять не нужно, просто вводите факты через форму.

## Логотипы поставщиков

Пришлите мне логотипы (PNG/SVG, желательно с прозрачным фоном, квадратные) —
я подскажу, как их подключить, либо сделайте сами:

1. Загрузите файл в `assets/logos/` через приложение GitHub (например
   `assets/logos/mts.png`).
2. В админке откройте **Поставщики → редактировать** нужного поставщика и в
   поле «Путь к файлу логотипа» впишите `assets/logos/mts.png`.

Если логотип не указан — вместо него показывается эмодзи/буква на цветном
фоне, поэтому сайт выглядит завершённым даже без картинок.

## Установка как приложение на iPhone

Откройте сайт в Safari → кнопка «Поделиться» → **На экран «Домо»**. Появится
иконка `Densel`, открывающаяся в полноэкранном режиме без адресной строки.
Гто работает и у вас, и у сестры — у каждого будет своя иконка и своя сессия
входа на устройстве.

## Важно про безопасность

Это осознанно простое клиентское решение без backend-сервера:

- Публичный репозиторий = кто угодно с прямой ссылкой на `data.json` увидит хэши
  паролей (не сами пароли) и все суммы платежей. Для двух близких людей
  и данных уровня «сколько заплатили за ЖКХ» это приемлемый риск, но не
  используйте здесь банковские реквизиты или пароли от других сервисов.
- Если хотите закрыть репозиторий полностью — сделайте его **Private** (это
  доступно бесплатно), но тогда GitHub Pages потребует платный план GitHub Pro
  (~4 $/мес), либо разверните сайт через Netlify Drop с приватным исходником —
  файлы для этого варианта такие же, просто загрузите их как есть на
  [Netlify Drop](https://app.netlify.com/drop) без всякого GitHub.
- Токен из шага 1 хранится только в браузере устройства, где вы его ввели.
  При смене телефона/браузера введите его заново в **Настройки**.

## Частые проблемы

- **Изменения не появляются у сестры** — после каждого сохранения просите её
  обновить страницу — `data.json` кэшируется браузером на несколько минут.
- **После обновления кода сайт выглядит по-старому** — service worker кэширует
  интерфейс офлайн; закройте вкладку и откройте заново.
- **«Ошибка сохранения в GitHub»** — обычно значит, что токен просрочен, не тому
  репозиторию выдан доступ, или недостаточно прав (`Contents: Read and
  write` обязательно).
