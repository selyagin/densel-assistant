# Платежи, история и статистика — техническая спецификация

## Цель
Убрать вводящее в заблуждение отображение будущих неоплаченных начислений, сделать блоки платежей согласованными и превратить статистику в наглядный инструмент анализа.

## 1. Модель платежа
Для каждого начисления хранить и не смешивать следующие значения:
- `amount` — начисленная сумма по квитанции.
- `paidAmount` — фактически оплаченная сумма.
- `billingMonth` — расчётный месяц в формате `YYYY-MM`.
- `dueDate` — срок оплаты в формате `YYYY-MM-DD`.
- `paymentDate` — дата оплаты или `null`.

Сумма начисления не должна выводиться из `paidAmount`: у будущего неоплаченного счёта `paidAmount` может быть 0, но `amount` должен содержать сумму квитанции.

## 2. Вычисляемые статусы
Статус определяется на текущую локальную дату пользователя:
- `paid` — `paidAmount >= amount`, период уже наступил или совпадает с текущим.
- `paid_early` — `paidAmount >= amount` и `billingMonth` позже текущего месяца.
- `partial` — `paidAmount > 0 && paidAmount < amount`; остаток равен `amount - paidAmount`.
- `due` — период наступил, `paidAmount < amount`, а `dueDate` сегодня или позже.
- `overdue` — `paidAmount < amount` и `dueDate` раньше сегодняшней даты.
- `planned` — `billingMonth` позже текущего месяца и `paidAmount === 0`.

## 3. История платежей
В историю включать только `paid`, `paid_early`, `partial`, `due` и `overdue`.

Не включать `planned`: будущие неоплаченные начисления не являются ни долгом, ни событием истории. Поэтому запись будущего интернета не должна отображаться как «Ожидается» и «0 ₽».

Для каждой записи показывать:
- название услуги;
- расчётный месяц;
- `amount` для начисления;
- `paidAmount` для оплаченной суммы, если она есть;
- остаток `max(amount - paidAmount, 0)` для неполной оплаты;
- дату оплаты, если она существует;
- явный статус.

Текст статусов:
- `paid`: «Оплачено»;
- `paid_early`: «Оплачено заранее»;
- `partial`: «Оплачено частично»;
- `due`: «К оплате до ДД.ММ.ГГГГ»;
- `overdue`: «Просрочено».

## 4. Карточка «К оплате»
Карточка должна быть кнопкой во всех состояниях.

Если есть `due`, `partial` или `overdue`, при нажатии прокрутить к разделу платежей и включить фильтр соответствующих неоплаченных записей. Первая запись получает фокус.

Если оплачивать нечего, перейти к разделу платежей и вывести ненавязчивое сообщение: «На данный момент неоплаченных начислений нет». История и фильтры остаются доступны.

Оформление:
- долг/просрочка: коралловый акцент;
- есть сумма к оплате без просрочки: бирюзовый акцент;
- к оплате 0 ₽: нейтральная граница и зелёное подтверждение «Всё оплачено».

Анимация внимания не запускается при первоначальном рендере, обновлении данных, таймере или возврате на экран. Она запускается только по `click`/клавиатурной активации карточки, идёт не более 600 мс и затем удаляет свой CSS-класс. При `prefers-reduced-motion: reduce` анимация выключена.

## 5. Раздел «Платежи»
Заменить статичный заголовок и отдельную кнопку «История и сортировка» на одну кнопку «Платежи». Нажатие открывает существующие историю, фильтры, сортировку и выбор периода.

Рекомендуемое содержимое кнопки:
- основной текст: «Платежи»;
- вторичный текст: «История, фильтры и сортировка»;
- иконка раскрытия/сортировки справа.

## 6. Статистика
Добавить сверху сводку за выбранный период:
- «Начислено» = сумма `amount`;
- «Оплачено» = сумма `paidAmount`;
- «Остаток» = сумма `max(amount - paidAmount, 0)` только по наступившим периодам;
- при отсутствии остатка выводить «Просрочек нет».

График динамики:
- начисления — фиолетовая полупрозрачная область или столбцы;
- оплаты — бирюзовая линия с точками;
- просрочки — красные маркеры в соответствующих месяцах;
- по касанию/наведению выводить месяц, начислено, оплачено и остаток.

Кольцевая диаграмма по поставщикам:
- ЖКХ — фиолетовый;
- Интернет — бирюзовый;
- Капитальный ремонт — оранжевый;
- новые поставщики получают устойчивые контрастные цвета палитры.

В центре кольца отображать итог: «N ₽ оплачено за период». Легенда выводит цвет, название, рублёвую сумму и долю. Нажатие на сегмент открывает/применяет фильтр соответствующего поставщика в истории.

## 7. Критерии приёмки
1. Будущий неоплаченный платёж не виден в истории.
2. При наступлении периода выводится фактическая сумма `amount`, а не 0 ₽.
3. Будущий полностью оплаченный платёж показан как «Оплачено заранее».
4. Просрочка определяется только по `dueDate < today` и непогашенному остатку.
5. Карточка «К оплате» работает и при сумме 0 ₽.
6. Анимация карточки не запускается без действия пользователя.
7. Одна кнопка «Платежи» заменяет старые заголовок и кнопку истории.
8. На статистике разные поставщики, начисления, оплаты и просрочки различимы визуально.
